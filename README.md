# Ассемблер и интерпретатор УВМ (вариант 30)

Учебная виртуальная машина (УВМ): стековая машина с общей памятью команд и данных. Проект на Python 3.8+; единственная
внешняя зависимость - PyYAML (разбор YAML).

```text
pip install -r requirements.txt

python3 -m src.assembler программа.yaml результат.bin [--test]
python3 -m src.interpreter результат.bin дамп.json --range НАЧАЛО:КОНЕЦ
```

То же через `./run.sh asm ...` и `./run.sh vm ...` (Windows: `run.bat asm ...`, `run.bat vm ...`).

## Спецификация УВМ

Команда занимает 3 байта (24 бита, младший байт первым - little-endian). Поле A (биты 0-6) - код операции,
поле B - операнд (начинается с бита 7).

| Команда | A | Поле B | Действие | Тест из спецификации |
|---|---|---|---|---|
| загрузка константы | 63 | биты 7-16 (10 бит) - константа | кладёт B на стек | A=63, B=61: `0xBF, 0x1E, 0x00` |
| чтение из памяти | 7 | нет | снимает адрес с вершины стека, кладёт на стек значение по этому адресу | A=7: `0x07, 0x00, 0x00` |
| запись в память | 3 | биты 7-19 (13 бит) - адрес | снимает значение с вершины стека, записывает по адресу B | A=3, B=629: `0x83, 0x3A, 0x01` |
| вычитание | 44 | биты 7-19 (13 бит) - адрес | первый операнд - память[B], второй - память[элемент, снятый со стека]; кладёт на стек `память[B] - память[снятый адрес]` | A=44, B=975: `0xAC, 0xE7, 0x01` |

## Язык ассемблера (YAML)

Программа - **список** команд. Команда с операндом записывается как `имя: число`, команда без операнда - просто
`имя` (допустимо и `имя:` без значения). Комментарии YAML (`#`) разрешены, числа можно писать и в шестнадцатеричном
виде (`0x1F`).

| Запись | Команда | Операнд |
|---|---|---|
| `- load_const: 61` | загрузка константы | целое 0..1023 |
| `- read` | чтение из памяти | не нужен |
| `- write: 629` | запись в память | адрес 0..8191 |
| `- sub: 975` | вычитание | адрес 0..8191 |

Пример (`examples/spec_tests.yaml`, четыре теста из спецификации):

```yaml
- load_const: 61
- read
- write: 629
- sub: 975
```

Ошибки ассемблера (сообщение с номером команды и код завершения 2): файл не найден или это каталог; некорректный
YAML; программа - не список или пустая; элемент не вида `имя` / `имя: значение`; неизвестная команда; для команды
без операнда указан операнд; операнд не указан, не целое число (в том числе `true`) или вне диапазона поля.

## Структура

```text
src/spec.py         команды, коды операций, размеры полей
src/ir.py           внутреннее представление команды (поля A и B)
src/codec.py        перевод команд в машинный код и обратно
src/machine.py      модель УВМ: общая память, стек, выполнение команд
src/interpreter.py  интерпретатор: командная строка, дамп памяти
src/assembler.py    ассемблер: разбор YAML и командная строка
examples/           программы на языке ассемблера (examples/errors - с ошибками);
                    tests/make_examples.py создаёт большие примеры
tests/              модульные тесты (unittest), скрипты демонстрации test_stageN.sh,
                    эталоны tests/expected, генератор примеров make_examples.py
run.sh, run.bat     запуск ассемблера и интерпретатора
```

Тесты: `python3 -m unittest discover -s tests`. Демонстрации этапов: `bash tests/test_stage1.sh` и т. д.

## Этап 2. Формирование машинного кода

- `codec.encode` переводит команду во внутреннем представлении в 3 байта: `слово = A | (B << 7)`, байты - от младшего к
  старшему (`0xBF, 0x1E, 0x00`).
- Ассемблер записывает результат в двоичный файл и выводит его размер в байтах (всегда 3 x число команд).
- В режиме `--test` для каждой команды печатаются байты в формате спецификации: `0xBF, 0x1E, 0x00`.
- Программа `examples/spec_tests.yaml` даёт ровно 12 байт - все четыре тестовые последовательности спецификации;
  скрипт сверяет вывод с `tests/expected/spec_bytes.txt` и сам двоичный файл с эталонными байтами.
- Новые ошибки: нельзя записать выходной файл (нет каталога, нет прав).

## Этап 3. Интерпретатор и операции с памятью

**Командная строка:** `python3 -m src.interpreter программа.bin дамп.json --range НАЧАЛО:КОНЕЦ` - двоичный файл
программы, файл для дампа памяти (JSON) и диапазон адресов дампа (оба адреса включительно, 0..8191).

**Модель памяти** (`src/machine.py`). Память команд и данных объединена: один массив из 8192 ячеек (адрес - 13 бит,
как в поле B). Ячейка хранит целое число со знаком (32 бита, результат оборачивается). Двоичная программа
загружается с адреса 0 по одному байту в ячейку; остальные ячейки - данные. Команды выбираются из той же памяти, поэтому
запись по адресам программы меняет сами команды (если в ячейку кода попадает число не из диапазона 0..255, при выборе
команды будет ошибка). Отдельно есть стек значений.

**Цикл интерпретации:** выбрать 3 ячейки по адресу `pc` -> перевести в промежуточное представление
(`codec.decode`) -> выполнить -> `pc += 3`; цикл идёт, пока `pc` внутри загруженной программы.

**Команды этапа:** загрузка константы, чтение и запись в память (вычитание добавлено на этапе 4).

**Дамп** - JSON: `range` (начало и конец) и `memory` (адрес -> значение):

```json
{"range": [200, 209], "memory": {"200": 11, "201": 22, "...": "..."}}
```

**Ошибки:** нет файла программы или нельзя записать дамп; неверный диапазон (`abc`, `5:1`, выход за 8191);
размер программы не кратен 3 или не помещается в память; неизвестный код операции; пустой стек; адрес вне памяти;
испорченная команда в памяти. Код завершения: 2 - ошибки аргументов и файлов, 1 - ошибки выполнения.

**Тестовая программа** `examples/copy_array.yaml` (создана `tests/make_examples.py`): записывает массив из пяти
элементов в ячейки 200..204 командами `load_const` + `write`, затем копирует его в 205..209: для каждого элемента
`load_const адрес` -> `read` -> `write адрес_копии`.

## Этап 4. Арифметико-логическое устройство (АЛУ)

- Реализована команда вычитания `sub: B` (`Machine.sub`): снимает со стека адрес, берёт первый операнд `память[B]` и
  второй операнд `память[снятый адрес]`, кладёт на стек `первый - второй`. Результат - 32-битное число со знаком
  (может быть отрицательным; при переполнении оборачивается).
- Новые ошибки: пустой стек при вычитании; адрес, снятый со стека, вне памяти - в том числе отрицательный, когда
  результат вычитания используется как адрес.
- Тестовая программа `examples/sub_demo.yaml`: в ячейки 300 и 301 записаны 100 и 58; далее `302 = 300 - 301 = 42`,
  `303 = 301 - 300 = -42`, `304 = 300 - 300 = 0`, `305 = 302 - 303 = 84`. Для каждого вычитания программа делает
  `load_const адрес_второго_операнда` -> `sub адрес_первого` -> `write адрес_результата`. Скрипт проверяет значения в дампе
  и показывает ошибки.

## Этап 5. Выполнение тестовой задачи

**Задача:** поэлементно выполнить команду вычитания над двумя векторами длины 10; результат записать во второй вектор.
Вектор 1 лежит в ячейках 400..409, вектор 2 - в 410..419; после выполнения `Вектор2[i] = Вектор1[i] - Вектор2[i]`,
вектор 1 не меняется.

**Программа** (`examples/vector_sub_N.yaml`, создаётся `tests/make_examples.py`, 70 команд = 210 байт):

1. Данные записываются командами `load_const значение` + `write адрес` (20 элементов, 40 команд). Константа - 10 бит,
   поэтому исходные значения лежат в диапазоне 0..1023, а результаты могут быть и отрицательными.
2. Для каждого `i` (10 раз, 30 команд): `load_const 410+i` (адрес второго элемента) -> `sub 400+i` (первый операнд -
   память[400+i], второй - память[410+i]) -> `write 410+i` (результат во второй вектор).

Адреса данных (400 и выше) лежат за пределами программы (первые 210 ячеек), поэтому код не портится.

**Три примера** с разными данными:

| Пример | Вектор 1 | Вектор 2 | Что проверяет |
|---|---|---|---|
| `vector_sub_1` | 90, 80, 70, 60, 50, 40, 30, 20, 10, 100 | 1, 2, ..., 10 | положительные разности |
| `vector_sub_2` | 5, 4, 3, 2, 1, 0, 7, 8, 9, 6 | 10, 20, ..., 100 | отрицательные разности |
| `vector_sub_3` | 0, 1023, 500, 512, 1, 0, 1023, 255, 256, 1000 | 0, 0, 500, 513, 1023, 1023, 1023, 1, 255, 999 | нули, равные элементы, граничные значения |

Дамп памяти `--range 400:419` содержит оба вектора; скрипт сравнивает результат с вычислением на Python
(`Вектор1 - Вектор2`) и проверяет, что вектор 1 не изменился. Те же проверки есть в модульных тестах
(`tests/test_examples.py`).

Демонстрация (`bash tests/test_stage5.sh`):

```text

$ python3 -m src.assembler examples/vector_sub_1.yaml build/vector_sub_1.bin
Размер двоичного файла: 210 байт
```

## Принятые решения и ограничения

- Спецификация не задаёт размер памяти и ячейки. Принято: 8192 ячейки (адрес - 13 бит), значение ячейки - 32-битное целое
  со знаком; программа лежит с адреса 0, по байту в ячейке.
- Дамп содержит адреса диапазона `НАЧАЛО:КОНЕЦ` включительно.
- Выполнение заканчивается, когда `pc` выходит за конец загруженной программы; команд перехода в УВМ нет.
- YAML разбирается библиотекой PyYAML (`pip install -r requirements.txt`).
